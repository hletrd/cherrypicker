## MEDIUM

### S7-SEC-01: HTML report `esc()` still incomplete — XSS risk

**File:** `packages/viz/src/report/generator.ts:31-40`
**Confidence:** High

The `esc()` function handles 7 entities (`& < > " ' \ /`) plus null byte. It does NOT handle:
- Backspace (`\x08`) — can break HTML parsing in older browsers
- Form feed (`\x0c`) — can cause rendering issues
- Vertical tab (`\x0b`) — same
- Control characters U+0001-U+001F (except those explicitly handled)

More critically, `esc()` does not normalize or reject control characters. Malicious merchant names or category labels containing these could produce unexpected HTML behavior.

**Scenario:** A crafted transaction with merchant name containing control chars could bypass naive XSS filters.

**Fix:** Use a comprehensive HTML entity encoder or the `he` library. Alternatively, add explicit rejection of control characters.

### S7-SEC-02: Missing CSP in HTML reports

**File:** `packages/viz/src/report/generator.ts` (template)
**Confidence:** Medium

HTML reports generated by `generateHTMLReport` lack a Content-Security-Policy meta tag. If the report file is opened in a browser and the template or data is somehow compromised, there is no defense-in-depth against script execution.

**Fix:** Add `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'none'; ...">` to the report template.

## LOW

### S7-SEC-03: `validateFilePath` symlink check only when `mustExist` is true

**File:** `tools/cli/src/validation.ts:36-49`
**Confidence:** Low

Symlink detection is gated behind `options.mustExist`. A caller passing `mustExist: false` will not detect symlinks. While most callers likely pass `mustExist: true` for input files, this inconsistency is a latent risk.

**Fix:** Move symlink check outside the `mustExist` branch, or always check symlinks when the path exists.
